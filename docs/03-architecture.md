# 03 — المعمارية (Architecture)

## 1. الصورة الكاملة

```
              ┌──────────── الطالب / المؤسس (جوال أو متصفح — PWA قابل للتثبيت) ───────────┐
                                               │ HTTPS
                                ┌──────────────▼───────────────┐
                                │      apps/web  (Next.js)     │
                                │  • صفحات عامة (SSR + SEO)    │
                                │  • تطبيق الطالب  /app         │
                                │  • لوحة الإدارة  /admin       │
                                │  • API: Route Handlers +      │
                                │    Server Actions             │
                                │  • المصادقة والصلاحيات        │
                                └───┬──────────┬──────────┬────┘
                                    │          │          │
                     ┌──────────────▼──┐  ┌────▼─────┐  ┌─▼─────────────────────┐
                     │   PostgreSQL     │  │ تخزين    │  │ Claude API             │
                     │ • البيانات       │  │ ملفات    │  │ • المساعد الذكي (RAG)  │
                     │ • بحث tsvector   │  │ خاص (S3) │  │ • الاستخراج والتصنيف   │
                     │ • pg_trgm        │  └────▲─────┘  │ • OCR بالرؤية          │
                     │ • pgvector       │       │        ├────────────────────────┤
                     │ • طابور المهام   │       │        │ Embeddings API         │
                     └────────▲─────────┘       │        └─────────▲──────────────┘
                              │      ┌──────────┴──────────────────┴──┐
                              └──────┤  services/ingest (Python)     │
                                     │  Worker يسحب المهام من الطابور │
                                     │  استخراج ← تطبيع ← تقطيع ←     │
                                     │  استخراج أسئلة ← تصنيف ←       │
                                     │  كشف تكرار ← embeddings        │
                                     └────────────────────────────────┘
```

**لماذا هذا الشكل؟**
- **تطبيق واحد (Next.js)** يخدم الموقع العام والطالب والإدارة: فريق صغير، نشر واحد، أنواع TypeScript مشتركة من قاعدة البيانات حتى الواجهة.
- **Worker منفصل بلغة Python** لأن أفضل أدوات معالجة PDF/Word/OCR للعربية في Python، ولأن المعالجة بطيئة (دقائق للملف) ولا يجب أن تعطل الموقع.
- **قاعدة واحدة PostgreSQL** تقوم بدور: قاعدة البيانات + محرك البحث + قاعدة المتجهات + طابور المهام. أقل عدد من الخدمات = أقل تكلفة وأعطال. ننفصل عنها فقط عندما تفرض الأرقام ذلك.

## 2. وحدات النظام (Modules)

| الوحدة | المسؤولية | أهم ما فيها |
|---|---|---|
| `identity` | الحسابات والأدوار | تسجيل برمز تحقق للبريد، Google، Apple؛ أدوار طالب/محرر/مدير |
| `content` | المحتوى المنشور | التصنيف (اختبار ← مجال ← محور ← موضوع ← مفهوم)، الأسئلة، الدروس، المصادر، سجل التعديلات |
| `ingestion` | خط معالجة الملفات | الرفع، المهام، المقاطع، الأسئلة المستخرجة، طابور المراجعة، النشر |
| `practice` | التدريب | جلسات بنك الأسئلة، الحفظ، العلامات، البلاغات |
| `assessment` | الاختبارات | القوالب، تجميع الاختبار حسب الأوزان، المؤقت، التصحيح، التحليل، تحديد المستوى |
| `learning-engine` | "دماغ" المنصة | الإتقان لكل محور، المراجعة المتباعدة (FSRS)، مولّد خطة المذاكرة، مؤشر الجاهزية |
| `tutor` | المساعد الذكي | البحث في المصادر (RAG)، أدوات المساعد، الاستشهادات، حصص الاستخدام |
| `search` | البحث | بحث هجين: نصي + تقريبي + دلالي |
| `analytics` | التحليلات | مهام ليلية: صعوبة الأسئلة، معامل التمييز، أصعب المحاور، نشاط المستخدمين |
| `billing` | الدفع (لاحقًا) | باقة "حتى يوم اختبارك" عبر بوابة دفع سعودية |

## 3. هيكل المستودع (Monorepo)

```
rushd/
├─ apps/
│  └─ web/                      Next.js (App Router)
│     ├─ app/(marketing)/       الصفحات العامة
│     ├─ app/(student)/app/     تطبيق الطالب
│     ├─ app/(admin)/admin/     لوحة الإدارة
│     ├─ app/api/               endpoints (الرفع، المساعد بالبث، webhooks)
│     └─ components/ · lib/
├─ packages/
│  ├─ db/                       Prisma schema + migrations (منها SQL خام للبحث) + seed
│  ├─ core/                     منطق نقي مختبر: التطبيع العربي، التصحيح، الإتقان،
│  │                            FSRS، مولّد الخطة، تجميع الاختبار، مؤشر الجاهزية
│  ├─ ai/                       عميل Claude، الـ prompts بأرقام نسخ، مخططات المخرجات، أدوات المساعد
│  └─ ui/                       design tokens + مكونات RTL
├─ services/
│  └─ ingest/                   Python worker + اختبارات pytest بعينات ذهبية
├─ content/
│  ├─ inbox/                    ملفاتك الخام (مستودع خاص)
│  ├─ taxonomy/                 المجالات والمحاور كملفات YAML (تُزرع في القاعدة)
│  └─ fixtures/                 عينات اختبار للـ pipeline (منها ملف 1440)
├─ e2e/                         اختبارات Playwright
├─ docs/                        هذه الوثائق
└─ .github/workflows/           CI: lint, typecheck, test, build
```

**لماذا `packages/core` منفصل؟** لأن أهم منطق في المنتج (كيف نحسب الإتقان؟ متى يعود السؤال الخاطئ؟ كيف تُبنى الخطة؟) يجب أن يكون **دوال نقية** مختبرة بمئات الحالات، بعيدًا عن الواجهة وقاعدة البيانات.

## 4. قرارات تقنية جوهرية

### 4.1 الاختبارات والمؤقت
- المؤقت **يحسبه الخادم** (`deadlineAt`)، والواجهة تعرض العد فقط. تحديث الصفحة أو انقطاع النت لا يعيد الوقت ولا يضيع الإجابات.
- كل إجابة **تُحفظ فورًا** (autosave)، والتسليم بعد انتهاء الوقت تلقائي.
- **الإجابة الصحيحة لا تُرسل للمتصفح** قبل التحقق، فلا يمكن كشفها من أدوات المطور.
- الترتيب العشوائي للأسئلة والخيارات **ببذرة محفوظة** في المحاولة، فتُعرض المراجعة لاحقًا بنفس الترتيب.
- **تجميع الاختبار التجريبي حسب أوزان المجالات الرسمية** (blueprint)، مع تجنب الأسئلة التي رآها الطالب مؤخرًا قدر الإمكان.

### 4.2 محرك التعلم (`learning-engine`)
- **الإتقان لكل محور:** متوسط متحرك يعطي المحاولات الحديثة وزنًا أكبر، ويخصم الصح الموسوم "تخمين"، ويُعامل المحور ذا المحاولات القليلة كـ "غير معروف" بدل "ضعيف".
- **المراجعة المتباعدة:** خوارزمية FSRS (مكتبة `ts-fsrs`)، ونحوّل نتيجة السؤال إلى تقييم: خطأ = Again، صح بتخمين = Hard، صح بتردد = Good، صح بثقة وسرعة = Easy.
- **مولّد الخطة:** خوارزمية حتمية قابلة للاختبار (ليست نموذج لغة):
  1. السعة اليومية = الوقت المتاح ÷ متوسط وقت السؤال/الدرس.
  2. ترتيب المحاور حسب الأولوية = وزن المجال × (1 − الإتقان) × عامل التكرار في المصادر.
  3. ثلاث مراحل: تأسيس (دروس + تدريب)، ثم تدريب مختلط + اختبار تجريبي دوري، ثم آخر 3 أيام مراجعة مكثفة واختبار شامل.
  4. المراجعة المستحقة (FSRS) تُحجز لها دقائق يوميًا أولًا.
  5. **إعادة تخطيط تلقائية** كل ليلة إذا تأخر الطالب أو تغيّر إتقانه.
- **مؤشر الجاهزية:** مجموع (وزن المجال × الإتقان) مع خصم لضعف التغطية، يُعرض كنطاق تقريبي مع توضيح أنه تقدير وليس وعدًا.

### 4.3 المساعد الذكي (`tutor`)
- نموذج Claude مع **أدوات** يستدعيها بنفسه:
  - `search_sources(query)`: بحث هجين في مقاطع الملفات والدروس والأسئلة المنشورة.
  - `get_question(id)`: السؤال والشرح ومصادره.
  - `get_my_weaknesses()`: أضعف المحاور وأكثر الأخطاء.
  - `build_quiz(topic, difficulty, count)`: **يسحب من البنك المعتمد** ولا يخترع أسئلة.
- قواعد التأسيس (grounding):
  - كل إجابة تستشهد بالمقطع والمصدر والصفحة.
  - إن لم يجد في المصادر، يقول ذلك صراحة ويوسم الجواب: "من المعرفة العامة، وغير موثق في مصادر المنصة".
  - إن طلب الطالب "أسئلة أصعب" ولم تكفِ أسئلة البنك، يولّد أسئلة **موسومة "مولّدة بالذكاء الاصطناعي، غير مراجعة"**، ولا تدخل البنك إلا بعد مراجعة.
- بث الرد كلمة كلمة (streaming)، وحصة يومية لكل مستخدم للتحكم في التكلفة، وتخزين مؤقت (prompt caching) لتعليمات النظام.

### 4.4 البحث
- النص يُطبّع (نفس الدالة في الفهرسة والبحث) + مرادفات المجال (المرشد ↔ الموجه) + حذف خفيف للسوابق (و/ف/ب/ل + ال)، لأن المُجذِّع العربي المدمج في PostgreSQL فشل في الاختبار على كلمات مثل "توجيه/التوجيه" ← بحث نصي `tsvector` + بحث تقريبي `pg_trgm` يتحمل الأخطاء الإملائية ← بحث دلالي بالمتجهات للمعنى ("عقاب بسحب الامتيازات" يجد "تكلفة الاستجابة") ← دمج النتائج (Reciprocal Rank Fusion).
- النتائج مجمعة: أسئلة، مفاهيم، محاور، دروس.

### 4.5 الأمان والخصوصية
- صلاحيات على مستوى الخادم لكل مسار `/admin` وكل Server Action.
- الملفات في تخزين خاص، تُفتح بروابط موقعة مؤقتة.
- حدود معدل الطلبات (rate limiting) على الدخول والمساعد والبحث.
- سجل تدقيق (`AuditLog`) لكل تعديل إداري.
- **نظام حماية البيانات الشخصية (PDPL):** موافقة صريحة، سياسة خصوصية عربية، تصدير البيانات وحذف الحساب من الإعدادات، وأقل قدر من البيانات (لا نطلب رقم الهوية).
- علامة مائية خفيفة باسم المستخدم في المحتوى المدفوع للحد من التسريب.

### 4.6 الأداء
- الصفحات العامة تُولّد مسبقًا (Static/ISR)، وتطبيق الطالب ديناميكي.
- السؤال التالي يُجلب مسبقًا أثناء قراءة الشرح.
- PWA: تثبيت على الشاشة الرئيسية، وتخزين الدروس المفتوحة للقراءة دون اتصال.
- ميزانية أداء: أول عرض للمحتوى أقل من ثانيتين على شبكة 4G متوسطة، وحجم JavaScript للصفحة الأولى محدود ومراقب في CI.

### 4.7 المراقبة والجودة
- Sentry للأخطاء، سجلات منظمة، ولوحة **تكلفة الذكاء الاصطناعي** اليومية.
- الاختبارات: Vitest للمنطق، Playwright لتدفقات الطالب والإدارة على مقاس جوال، pytest للـ pipeline بعينات ذهبية، وفحص وصولية (axe).
